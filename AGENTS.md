# TikTok Live Reader — project notes

## Run

```
npm install
npm start          # node server.js, serves index.html + WebSocket on the same port
```

Open `http://localhost:3000`. There is no test suite, lint, or build step; verification is manual:
start the server, connect to a username that is currently live, and confirm chat/gift/join events
appear in the browser and in the server log.

## Environment variables

| Var | Required | Purpose |
| --- | --- | --- |
| `PORT` | no (default 3000) | HTTP + WebSocket port |
| `SIGN_API_KEY` | no | Euler Stream API key. Without it, signing is anonymous and rate limited per IP — unreliable on shared hosting like Render. Free key at https://www.eulerstream.com |
| `PROXY_URL` | no | e.g. `http://user:pass@host:80`. Applied to both the HTTP client and the WebSocket. |

## Why signing (and Euler Stream) is unavoidable

TikTok's webcast endpoints reject requests that lack valid signature query params (`X-Bogus`,
`msToken`, ...) generated by obfuscated client JS. `tiktok-live-connector` delegates that to Euler
Stream. This is not optional unless you run your own sign server (see
https://www.eulerstream.com/docs/sign-server/custom-sign-servers).

Historical failure worth remembering: v1.x of the library called the now-removed
`https://tiktok.eulerstream.com/webcast/sign_url` route (404) and then a Cloudflare-blocked
fallback `https://tiktok-sign.zerody.one/` (403). The v1 signer overwrites its error variable per
host, so the only visible symptom was a misleading `403` plus endless
`"TikTok does not offer a websocket upgrade"` / `"Failed to retrieve the initial room data"`
reconnect loops. Room ID resolution succeeding while connect fails points at signing, not at the
streamer being offline.

## v2 library field mapping (breaking change from v1)

`tiktok-live-connector` v2 emits **raw protobuf**, not v1's flattened objects. Key differences,
verified against live traffic:

| Meaning | v1 | v2 |
| --- | --- | --- |
| chat text | `data.comment` | `data.content` |
| username (`@handle`) | `data.uniqueId` | `data.user.displayId` |
| display name | `data.nickname` | `data.user.nickname` |
| moderator | `data.isModerator` | `data.userIdentity.isModeratorOfAnchor` |
| follower | `data.followRole >= 1` | `data.userIdentity.isFollowerOfAnchor` |
| gift name / value | `data.giftName`, `data.diamondCount` | `data.gift.name`, `data.gift.diamondCount` |
| gift streak type | `data.giftType` | `data.gift.type` |

`user.payGrade.level` and `user.fansClub` come back empty over the anonymous WebSocket. The
reliable source for levels is `user.badgeList[]`, matched on `sceneType` and read from
`privilegeLogExtra.level`:

- `sceneType 8` → user grade badge, used as `gifterLevel`
- `sceneType 10` → fan club badge, used for `isFan`

Room info (`state.roomInfo`) returns `status_code 4003110` with no title for anonymous clients, so
the stream title falls back to `"Live"`. An API key or session is needed for the real title.

## WebSocket contract (server -> browser)

`connected`, `chat`, `gift`, `member`, `status`, `reconnecting`, `error`.

`chat`/`gift`/`member` all carry `user`, `displayName`, `isMod`, `isFollower`, `isFan`,
`gifterLevel`. The browser's fan filter compares `gifterLevel` against a minimum level, so that
field must stay populated.

## TTS message templates

All spoken text comes from editable templates in the UI, persisted to `localStorage` via
`saveSettings()` / `applySettings()`. Each has a Hebrew and English variant:

| Event | Input IDs | Placeholders |
| --- | --- | --- |
| comment | `commentMsgTemplate`, `commentMsgTemplateEn` | `<username>`, `<comment>` |
| gift | `giftMsgTemplate`, `giftMsgTemplateEn` | `<username>`, `<gift>` |
| join | `joinMsgTemplate`, `joinMsgTemplateEn` | `<username>` |

Comment speech is built by `buildCommentSpeech(user, text, lang)`, the single source of truth for
both the TTS queue (`processQueue`) and click-to-read (`readItemAloud`). Do not reintroduce
hardcoded sentences like `` `${user} אומר: ${text}` `` in those functions.

`toggleSkipGenericNames` (on by default) drops the name for auto-generated TikTok handles so only
the message is read. Detection is `isGenericUsername()`: `/^user[._-]?\d{4,}$/i`, i.e. `user`
followed by 4+ digits (`user40550754416165`). It deliberately does NOT match mixed-character
handles like `userxx2a69lu32`, because those accounts usually have a real nickname, and the
frontend reads `displayName || user`.

## Removed features

The battle/match manager was deleted from both ends: server-side `linkMicBattle` / `linkMicArmies`
handlers and the `WebcastLinkmicBattleTaskMessage` byte-scraping, plus the frontend Match Manager
panel, `addBattleEvent()`, `toggleMatchPanel()`, the `battle_*` message handlers, and the `battle`
log category.

The `sessionid` input in the UI is intentionally kept but currently unused. v2 session auth needs
both `sessionId` and `ttTargetIdc` (see `CookieSessionBundle`), and the UI only collects the
former, so the server ignores it. Signing no longer depends on it.
